Why bqkit

Reading a large query result through the BigQuery REST API is slow. The Storage Read API streams rows in Avro over gRPC instead. bqkit wires that path into Spring Boot.

Query to Avro

Run a query into a destination table, then stream it in Avro through BigQueryReadClient.

Impersonation

Application Default Credentials, with optional service account impersonation.

Emulator tests

A @ServiceConnection for the BigQuery emulator with Testcontainers: no GCP project needed.

Backs off

Every bean steps aside when your application defines its own.

The read path

One call to query(sql, destination) runs three steps.

Modules

Use the core alone, or let the starter wire it for you.

Usage

bqkit is not released yet: build it locally with mvn install to use .

Each major version of bqkit targets one Spring Boot generation:

  • bqkit 1.0.x: Spring Boot 3.5, Java 21. This line only receives fixes.
  • bqkit 2.x: Spring Boot 4 (planned).

1. Add the starter

<dependency>
    <groupId>io.github.bqkit</groupId>
    <artifactId>bqkit-spring-boot-starter</artifactId>
    <version></version>
</dependency>

2. Configure

bqkit:
  bigquery:
    project-id: my-project
    impersonate-service-account: reader@my-project.iam.gserviceaccount.com # optional

3. Query

List<GenericRecord> rows = reader.query(
        "SELECT name FROM `my-project.shop.products` WHERE price > 1.5",
        TableId.of("shop", "query_result"));
query(sql, destination)

Truncates the destination table before writing, then reads it.

query(sql)

Reads the anonymous result table that BigQuery creates for the job.

readTable(table)

Reads an existing table.

Every bean backs off when the application defines its own. Defining a BigQueryConnectionDetails bean replaces the connection built from the properties.

Credentials

Set impersonate-service-account to read with a service account's permissions instead of your own.

Testing

Declare the emulator container: Spring Boot connects every bqkit bean to it.

<dependency>
    <groupId>io.github.bqkit</groupId>
    <artifactId>bqkit-test</artifactId>
    <version></version>
    <scope>test</scope>
</dependency>
@SpringBootTest
@Testcontainers
class ProductRepositoryTest {

    @Container
    @ServiceConnection
    static final BqkitBigQueryEmulatorContainer EMULATOR =
            new BqkitBigQueryEmulatorContainer();
}

BqkitBigQueryEmulatorContainer runs ghcr.io/goccy/bigquery-emulator:0.8.1 on project testproject and exposes the gRPC port of the Storage Read API.

Emulator limits

The emulator is not BigQuery. Keep these in mind when a test behaves differently from production.

Hyphenated project ids break Avro reads

The emulator builds the Avro namespace from the project id, so test-project (the Testcontainers default) fails. testcontainers-java#12123 proposes withProjectId.

bqkit uses testproject

query(sql) fails

The emulator names the anonymous result table after the job id, which is not a valid Avro name (bigquery-emulator#527).

Use query(sql, destination) in tests

WRITE_TRUNCATE is ignored

query(sql, destination) appends to the destination table instead of replacing it, so a second query into the same table returns the rows of both.

Use a distinct destination table per test, or drop it before each test

See also bigquery-emulator#508.

None of these limits affect BigQuery itself.

Build

mvn verify

The tests need Docker.
